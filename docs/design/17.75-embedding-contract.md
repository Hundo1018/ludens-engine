# 17.75 Embedding contract: threads, errors, units, memory, stepping

The rules a host engine (Godot, Unity, Unreal, a custom engine) relies on when
it embeds ludens-engine. 12.1's C ABI (`embed/capi.mojo`, `embed/ludens.h`)
cites this note for semantics; the C signatures and their freeze live there.

## 1. Threads

| Rule | Where it is enforced / tested |
|---|---|
| A `ContactScene6`, a `Runtime` and an `EmbedWorld` have **one owner thread at a time**. Nothing inside them takes a lock. Two threads calling into the same world concurrently is undefined. | design rule |
| The engine starts **no threads of its own** unless the dispatcher says so: every parallel fan-out (island solve, same-colour contact pairs, batched differentiable worlds, job-graph levels) goes through a `scheduler.dispatch.Dispatch`. | `test_dispatch`, `test_jobgraph` |
| `Dispatch.from_host(fn, ctx)`: the host's `fn(ctx, n, task, data)` must call `task(data, i)` exactly once for every `i` in `[0, n)` before returning, from **any threads, in any order**, and may run items inline on the calling thread. The result is bit-identical whatever it does (items write disjoint state). | `test_dispatch` (reversed host callback), `test_jobgraph` |
| Other dispatchers: `parallel` (runtime pool, default), `serial`, `reverse` (order-independence check), `work_stealing` (`scheduler.workstealing`). Same result under all five. | `test_dispatch` 10/10 |
| Not yet routed through `Dispatch`: the actor schedulers' `DispatchPolicy` (`scheduler/policy.mojo`) is a compile-time policy with no instance to carry a host context; `Parallel` there still uses the runtime pool. | known gap |
| Non-blocking stepping: `Runtime.begin_advance` (owner thread) → `Runtime.execute(handle)` (any **one** thread; nothing else may touch the runtime or its scene meanwhile) → `Runtime.finish(handle)` (owner thread). While a step is in flight the host reads `Runtime.published` (poses of the last completed tick), never the scene. | `test_async_step` |
| GPU: one `DeviceContext` per process, owned by the caller and passed in (`*_run_ctx`). Several contexts in one process hang. | CLAUDE.md, GPU tests |

## 2. Errors

Same classes as `docs/ARCHITECTURE.md` §2, stated from the host's side:

- **Invalid input at a public call** (bad handle, out-of-range index, a
  `SolverConfig` from untrusted input) → the call `raise`s; through the C ABI
  that becomes the error code 12.1 defines. Validate once at the boundary
  (`SolverConfig.validated()`).
- **The step itself never raises.** `ContactScene6.step` guards its invariants
  with `debug_assert` (terminates under `-D ASSERT=all`, free in release).
- **Wrong call order of the split step** (`begin` twice, `execute` / `finish`
  with a stale handle, `finish` before `execute` or twice, `teleport` /
  `despawn` while in flight) raises; `spawn_*` while in flight is a
  `debug_assert`. The runtime stays usable after the error.
- **Numerical failure** (NaN, divergence) → the body is quarantined at step end
  and `diag.counters.NAN_QUARANTINED` counts it; the simulation continues.
- **Capacity overflow** → drop the newest item and count it
  (`LOG_DROPPED`, `ARENA_OVERFLOW`, ...); `FrameArena.alloc` additionally raises
  so its caller can fall back.

## 3. Units and coordinates

- **SI** inside: metres, kilograms, seconds, radians. A host in other length
  units passes its own numbers and tells the solver its scale once:
  `UnitScale(per_meter).apply(cfg)` multiplies every absolute length tolerance
  (speculative margin, linear sleep threshold, restitution threshold, push-out
  speed cap). Angular thresholds, times and the soft-constraint knobs are
  unit-free. Checked by similarity (`test_unit_scale`): lengths × 2^k with
  `UnitScale(2^k)` keep a sphere's trajectory bit-identical; box and capsule
  contacts stay within 5e-3 (their manifolds are not exactly scale-equivariant
  yet -- open).
- **Right-handed**, `cross(+X, +Y) = +Z`; a positive angle about +Y takes +X to
  −Z (`test_conventions`).
- **`Quat` layout** `x, y, z, w`, `w` scalar.
- **Up axis**: the solver has none (gravity is an argument). Gameplay code is
  **Y-up**: `gameplay/character.mojo`, `gameplay/vehicle.mojo` (vehicle frame
  forward +X, up +Y, right +Z; default gravity (0, −9.8, 0)). A Z-up host
  (Unreal, Blender) converts at the boundary, once.
- **World scalar** `Float32` by default; `pixi run build-f64` builds every
  package with `Float64` (17.8).

## 4. Memory

- Per-frame scratch can live in host memory: `diag.arena.FrameArena.from_block(span)`
  carves typed spans out of a block the host owns and never frees it
  (`test_diag_arena`). Wiring the solver's per-step scratch through it is 17.79.
- Persistent storage (`BodySet`, `ColliderSet`, ECS columns) uses `List`,
  which in Mojo 1.1.0 has no allocator parameter (`struct List[T: AnyType, /]`),
  so it cannot be pointed at a host allocator without replacing the container.
  Until then the contract is "persistent memory is measurable and boundable"
  (17.79).

## 5. Determinism

Bit-identical results are promised for the same toolchain **and the same
compile target**: the golden output reproduces across hosts only with
`--target-cpu skylake` pinned (17.81 probe; the CPU model, not only the ISA
level, changes last digits). Dispatcher choice, thread count and item order do
not change results (§1).
