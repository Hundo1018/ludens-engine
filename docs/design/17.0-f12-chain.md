# Spec 17.0 F12 — Chain scope: dense solve to numerics, ground contact to collision

Audit F12 (docs/audits/2026-09-27-architecture.md §1.2). Behaviour-preserving: identity gate = every
pre-existing golden section byte-identical.

## Dense solve -> `numerics/dense.mojo`
- `solve_dense(var a, var b, n)`: the old `Chain.solve_h` moved verbatim (Gaussian elimination,
  partial pivoting, same operation order, so results are bit-identical). Never raises; singular input
  gives inf/NaN under IEEE (the step-end NaN quarantine is the net), n == 0 gives an empty list.
- `solve_dense_checked(..., tol)`: raises on a pivot `<= tol * max|a|` or a size mismatch, for API
  boundaries. The audit suggested Cholesky for the SPD mass matrix; not done, because swapping the
  factorisation changes rounding and would break the identity gate. A Cholesky variant is a separate,
  parity-tested seam row if wanted.
- Callers: `physics.chain`, `physics.floating`, `physics.constraints`, `benchmarks/bench_floating`.
  `Chain.solve_h` is removed (no shim: all callers were in-tree).

## Ground contact -> `collision`
- `collision.world_query.nearest_surface(cs, poses, p, filter, search)`: closest collider to a point,
  with `point_distance`'s signed distance and push-out normal.
- `Chain.resolve_ground(floor_y, ...)` became `Chain.resolve_contacts(world: ColliderSet, poses, ...)`.
  Same velocity/position split; contact active when `dist <= 0`, depth `-dist`, direction `normal`
  (was a hard-coded `y <= floor_y` and `up = (0,1,0)`). Box, sphere, capsule, hull report depth;
  trimesh/heightfield are unsigned distance, so they register on touch only (documented on
  `nearest_surface`); true mesh depth is the follow-up for 17.2.
- `ColliderSet.add_ground_slab(top, thickness, extent)` builds the old flat floor as a thick box.
  With `top - thickness` in `top`'s binade the distance is `p.y - top` bit for bit, which is why the
  golden `chain_contact` lines did not move.

## FloatingChain no longer writes Chain's fields
- `Chain.base_w/base_v/base_wa/base_va` are private (`_base_*`); `Chain.set_base_motion(w, v, wa, va)` is
  the single public way to move the root. `FloatingChain._sync` and the unit-acceleration assembly use it.
- Not done: passing the base motion as a per-call parameter (audit's stronger form). It touches every
  sweep signature and is the first step of 17.18/17.20 batching, not of F12.

## Tests
`tests/test_dense.mojo` (unit), `tests/test_chain_ground.mojo` (integration). Chain now imports
numerics and collision, so the mechanical tier rule (17.0b) reads every chain test as integration; ten
carry a one-line `(override: ...)` (precedent: test_body_set), `test_chain_contact` is honestly integration.
