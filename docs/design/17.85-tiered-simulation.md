# 17.85 — tiered simulation: time / space resolution per entity group

Question that opened this (2026-10-10): when the world holds far more entities than the player
can causally interact with, can the engine keep the simulation state at an appropriate time and
space resolution per entity, and can "which entities get which resolution" be a swappable module?

## Finding: today the answer is no

Every subsystem runs every registered system over every entity at full resolution each fixed
step. Verified against source (2026-10-10):

| layer | behaviour | evidence |
|---|---|---|
| scheduler | `System.apply` is a stateless static method; `Scheduler.tick` runs the whole pack; `FixedLoop` has one dt; job-graph levels give concurrency, not frequency | `scheduler/scheduler.mojo:26-46`, `scheduler/gameloop.mojo:45-49`, `scheduler/jobgraph.mojo:133-141` |
| ecs | queries are AND-intersections only; `Disabled` is a post-filter, still O(all matching) | `ecs/storage.mojo:27-54`, `ecs/pool.mojo:264-290` |
| physics freeze | `freeze` / `unfreeze` keep velocity, resume without a pop; binary; frozen bodies still enter broadphase + narrowphase as obstacles | `physics/solver6.mojo:552-576` |
| physics quality | `SimBudget` moves iters / substeps, but `_solve_islands_parallel` passes the same pair to every island | `physics/lod.mojo:58-94`, `physics/solver6.mojo:1393-1396` |
| physics sleep | islands sleep as a unit, but `refresh_islands` / `update_sleep` / `wake_island` are O(all bodies); sleeping–sleeping pairs are narrowphased every step and early-return in `impulse_inert` | `physics/islands.mojo:40-170`, `physics/solver6.mojo:776-810`, `physics/contact6.mojo:326` |
| broadphase | `BroadPhase.rebuild(items)` takes all n each step on every backend; only DBVH's tree work scales with movers | `collision/broadphase.mojo:29-40`, `collision/bp_dbvh.mojo:190-257` |
| soft / LBM / SPH / cloth | every body, every substep | `physics/soft_couple.mojo:46-57`, `fluid/lbm.mojo:535` |
| runtime | `gameplay/runtime.mojo` never references `DistanceLOD` / `SimBudget` | grep |
| world partition / interest management | not implemented (17.8, 17.16) | ROADMAP |

So the premise "interactable set ≪ total set" is never exploited: time resolution is not
adjustable at all, and spatial resolution exists only as physics freeze on/off.

## Why a seam (and not one policy)

The policy that decides *who gets which resolution* has several genuinely different variants,
each with a regime where it wins. That is the project's condition for a seam (CATEGORY.md §2):

| policy | decides tier from | advantage regime |
|---|---|---|
| `DistanceTiers` (generalises `DistanceLOD`) | distance to observer(s) → tier, with hysteresis | single player, open terrain |
| `CausalReach` | BFS from observers over the island / contact graph and event subscriptions; depth k → tier | several observers; indoor / partitioned spaces (near in distance, far in causality) |
| `BudgetTiers` (generalises `SimBudget`) | measured step cost → shift the tier thresholds or per-tier period | hard frame cap, heterogeneous hardware |
| `RoundRobin` | `id mod N` → phase; every entity ticks once per N steps regardless of position | uniform crowds without a focus (flocks, ecologies) |
| `AggregateTiers` | a far cluster → one centroid / statistical proxy | extreme distance, n ≫ 1e4 |

Parity anchor for all of them: a policy that returns tier 0 / period 1 for everything must leave
the world **bit-identical** to the current `Runtime.advance` (same rule 17.31 used).

## Design

### Tier assignment (the seam)

```mojo
struct TierPlan:
    # per entity (or per island, see below): tier 0 = full, higher = coarser
    var tier: List[UInt8]
    var period: List[UInt8]   # tick every `period` steps
    var phase: List[UInt8]    # which step in the period this one ticks on

trait TierPolicy:
    def assign[B: StorageBackend, Body: Body6](
        mut self, world: World[B], scene: ContactScene6[Body],
        observers: List[Vec3], step_index: Int, out plan: TierPlan)
```

- Lives in `gameplay` (needs world + scene + observers). Pure function of its inputs plus its own
  hysteresis state, so it is snapshot-friendly (17.40) and replay-safe (17.39): the plan is a
  function of state the snapshot already holds plus `step_index`.
- Observers are a list, not a point: that is what makes `CausalReach` and multi-player meaningful.

### Applying a plan

Three consumers, each attaching to a seam that already exists:

1. **Scheduler — time resolution.** `DeclaredSystem` gains `period() -> Int` (default 1) and the
   tier a system belongs to; a `TieredScheduler[S: Scheduler]` wrapper skips a system when
   `(step_index + phase) % period != 0`. Systems that cannot be skipped (contact events, pose
   sync) declare period 1. `FixedLoop` is untouched. Caveat: `Runtime.advance` does not go
   through any `Scheduler` (`gameplay/runtime.mojo:174-184`), so inside `Runtime` this consumer
   has nothing to wrap until user systems can be registered there (17.77 gap); until then the
   time-resolution half applies only to `FixedLoop.advance[S: Scheduler]` callers.
2. **ECS — active set.** A tag component `Tier[N]` rather than a `StorageBackend` change: the six
   backends stay as they are, archetype / reactive / sparse-set iterate O(active set) for free,
   and a system that only wants tier 0 queries `(Tier[0], ...)`. Retagging is a deferred structural edit: the add half exists (`SetBuffer.set`,
   `ecs/commands.mojo:109`), but `CommandBuffer` has only `despawn` / `relate` / `unrelate`
   (`ecs/commands.mojo:43-49`), so a deferred `remove` must land first (17.77 gap).
3. **Physics — space resolution per island.** Tier → `(iters, substeps, period)` per island:
   - `_solve_island` already takes `substeps, iters`; `_solve_islands_parallel` passes per-island
     values instead of the global pair (closes the 17.31 TODO).
   - period > 1 islands skip the solve on off-phase steps but integrate pose with the stored
     velocity (no freeze, no pop); the top tier freezes as today.
   - Island bookkeeping switches to an awake list so `update_sleep` / `wake_island` are O(awake).
   - `BroadPhase` gains `update_moved(items, moved: List[Int])` with a default that falls back
     to `rebuild`; DBVH implements it incrementally. Frozen / sleeping proxies are still present
     (they are obstacles) but never re-inserted.

Soft bodies, LBM and particles are out of scope for the first cut: they get a per-object `period`
through the same plan and otherwise keep their current path.

### What stays bit-identical

- `TierPolicy` = all-zero → `TieredScheduler` runs every system every step, every island gets the
  global `(iters, substeps)`, no `update_moved` call → same bytes as today. This is the parity
  test and it must hold on every backend / broadphase combination the existing parity matrix
  covers.

## Deliverables (per testing standard: ordinary / integration / extreme)

- `gameplay/tiers.mojo`: `TierPlan`, `TierPolicy`, `DistanceTiers`, `CausalReach`, `RoundRobin`,
  `BudgetTiers`; `scheduler/tiered.mojo`: `TieredScheduler`; physics changes listed above.
- `tests/test_tiers.mojo` (unit): plan shapes, hysteresis, `RoundRobin` covers every entity exactly
  once per period, `CausalReach` depth monotone in k.
- `tests/test_tiers_parity.mojo` (integration): all-zero plan == current `Runtime` bit-for-bit;
  the same plan applied through `DistanceTiers` and `CausalReach` on a scene where distance and
  causal reach coincide gives identical worlds.
- `tests/test_system_tiers.mojo` (system): 1e4 bodies, observer walks across the world; no body
  tier-changes with a penetration jump > contact slop; velocities continuous across tier changes;
  snapshot → restore → continue identical to the uninterrupted run (replay-safe).
- Extreme: observer inside a wall (causal reach ≠ distance), period change mid-contact, all
  observers removed (everything coarsens, nothing NaNs), tier flapping at the hysteresis band,
  island merge between two different tiers (takes the finer tier).
- `benchmarks/bench_tiers.mojo`: n ∈ {1e3, 1e4, 1e5} bodies with a fixed ~1e2 interactable set;
  columns: policy × (step cost, max penetration error vs full quality, velocity error at
  re-promotion). Report row added to `scripts/benchmark_report.md.in`.
- `docs/CATEGORY.md` §2: one row per policy variant (seam, parity test, bench row); replaces the
  17.31 "quality parameter seam" note, which had no trait behind it.

## Delivered (2026-10-12, first cut)

What landed and where it departs from the design above:

- **Physics, per island** (`ContactScene6.set_tier_table` / `set_body_tiers`, `_step_tiered`): a tier
  table of (iters, substeps, period) and a tier per body slot. An island takes the finest tier of its
  members (the merge rule) and its first member's slot index as its phase. A due island runs the same
  per-island substep loop as the island-parallel path, over `period * dt` -- **catch-up** rather than
  the "integrate pose with stored velocity on off-phase steps" the design proposed: integrating poses
  without contacts lets resting bodies sink into each other between solves, while catch-up keeps the
  solver's own non-penetration at a coarser step and loses no simulated time. Off-phase islands are not
  touched at all (their contacts keep their impulses for the next warm start). `period == 0` holds an
  island still (the freeze end of the seam, without converting bodies to static).
- **Parity anchor holds bit for bit**: all-tier-0 with tier 0 = the step's config reproduces the
  untiered step (QuatBody6 × BVH and persistent DBVH, ScrewBody6), because it is the island-parallel
  path run serially, which `test_islands_par` already pins to the serial step.
- **Policies** (`gameplay/tiers.mojo`): `DistanceTiers`, `CausalReach` (BFS over last step's contacts
  and the joints; statics do not conduct), `RoundRobin`, `BudgetTiers`. `AggregateTiers` (2026-10-17): resting islands beyond a radius go to a period-0 tier and are summarised as `ClusterProxy`s; a toucher wakes one by joining its island.
- **Time resolution for systems**: `scheduler/tiered.mojo` `TieredScheduler[S]` (period, phase) for
  `FixedLoop.advance` callers. `Runtime.advance_tiered[P]` applies a policy before each fixed tick.
- **Snapshot**: format v3 carries `step_index`, the tier table and the plan, so a restored scene solves
  the same islands on the same steps (`test_system_tiers`: snapshot at 150 + 60 resumed steps == 210
  uninterrupted). Policy state (hysteresis) is the caller's to copy alongside.
- **Fallback**: soft bodies, ccd, colored solving, drives or breakable joints run untiered and count
  `TIER_FALLBACK`.

Not done in this cut (kept in the ROADMAP entry): the ECS `Tier[N]` tag (needs 17.77's deferred remove
and component-type headroom), the awake list for sleep bookkeeping, `BroadPhase.update_moved`, and
per-object periods for soft bodies / LBM / particles.
