# 17.0h — the error policy on the paths Wave A touches, and diag wired into the solver

Contract: docs/ARCHITECTURE.md §2 (error classes → who detects / recovers / records / propagates).
Evidence: docs/audits/2026-09-27-architecture.md F10 and hotspots E1–E24 (path:line). The diag
package (layer 0) provides invariants, log ring, counters, trace spans, debug-draw.

## A. Invalid caller input → `raise` at the public boundary (tests assert the raise)
- ContactScene6: dynamic body with mass ≤ 0 or a zero/negative principal inertia (E1, E2);
  `step`/`step_soft` with substeps < 1, iters < 1, hertz ≤ 0, zeta < 0, dt ≤ 0 (E5) — `step_soft`
  is non-raising with many call sites: validate once in `SolverConfig` construction
  (`SolverConfig.validated() raises`) and have `step` `debug_assert` a validated config;
  bad index / stale BodyId in add_joint / set_filter / set_sensor / set_restitution / set_friction,
  restitution outside [0, 1] (E12).
- TriMesh / HeightField constructors: index ≥ vertex count, `len % 3 ≠ 0`, `len(h) ≠ nx·nz`,
  cell ≤ 0 (E13). SoftBody `box_lattice(n < 2)` (E4). Polygon / quickhull with < 3 distinct
  points (E14, E15). SpatialHashGrid `cell_size ≤ 0` (E17). AnimClip `fps ≤ 0`, `frames == 0`,
  `play(bad index)` (E23). `add_link_to(parent < -1)` (E18).
  Keep the list to APIs; inner loops never raise.

## B. Numerical failure → recover locally, count, keep stepping (E3, E7, E16, E19, E22)
- End-of-step NaN/Inf scan over dynamic bodies (one pass, not per iteration): a non-finite body is
  quarantined (velocity zeroed, pose restored to the last finite pose if kept, force-sleep,
  removed from warm-start cache) and counted (`NAN_QUARANTINED`), plus a WARN log record.
  Test: inject NaN into one body's velocity mid-run → stepping continues, other bodies unaffected
  (bit-identical to a run where that body was removed at that step, or at least finite and
  plausible — pick the strongest check that holds), counter == 1.
- Soft particle with w == 0 in coupling (E3): skip, no inf. Graph colouring beyond 64 colours
  (E7): fall back to serial for that island and count. `normalize` of a zero vector (E16): provide
  `normalize_or(v, fallback)`, use it where a zero normal is possible (sdf, clip, rng unit vector;
  fix rng's non-uniform cube sampling too if cheap). CG not converged (E19): fem checks
  `converged` before applying `dv`. Game loop clamp (E22/F16): drop the excess debt when
  max_steps clamps, count it, assert dt > 0 so alpha ∈ [0, 1].

## C. diag wired into the production solver path (定律 v3)
- Counters owned by ContactScene6 (`diag` field or a `Counters` member), readable by gameplay.
- Trace spans around solver phases (collect pairs / narrowphase / warm start / solve / integrate /
  sleep / soft pass / CCD), compiled out unless `LUDENS_TRACE`; bench overhead on vs off
  (bench_solver_scale) ≤ a few %.
- Debug-draw: when `LUDENS_DEBUG_DRAW` is defined, the solver emits contact points + normals and
  island colours into a DrawQueue the caller passes/owns; test asserts the command count equals the
  contact count on a known stack.
