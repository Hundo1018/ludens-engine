# 17.21 Python bindings, CVars, hot reload

## Shape

`python/ludens` is a pure-Python package: ctypes over the frozen C-ABI of 12.1 (`embed/ludens.h`).
`python/build_wheel.py` packages it with `libludens.so` and the shared libraries that library loads
from the Mojo toolchain (Mojo runtime ×4, libstdc++, libgcc_s). The result is a
`py3-none-linux_x86_64` wheel that installs with `pip install --no-index` into any CPython 3.8+.

Why ctypes over the C-ABI rather than a PythonModuleBuilder extension (the 12.2 plan):

- There is one ABI surface to freeze and test. Python, C and any later binding call the same 35
  functions.
- The wheel does not depend on the CPython ABI. The test installs it with the system 3.13; the repo's
  pixi Python is 3.14.
- Cost: ctypes adds about 0.2 µs per call plus about 0.2 µs per argument, so `Body.state()` costs
  1.4 µs against 13 ns natively. Batch calls cost the same per body as native: `World.poses_into`
  writes every pose in one call (8–13 ns per body). Python systems run once per tick, and on 1000
  bodies the step is 3 % slower than native.
- The client test (`client_check.py`) does not depend on how the package is built. A faster
  extension module can replace `_capi.py` later and must pass the same checks.

## Packaging details

- The Mojo linker writes the toolchain's lib directory into libludens.so's `RUNPATH`.
  `build_wheel.py` rewrites the string in place to `$ORIGIN`: the new value is shorter, so it fits
  with NUL padding. Before writing, it checks that no `DT_NEEDED` / `DT_SONAME` string shares those
  bytes. No patchelf is needed.
- The bundled runtime libraries already carry `$ORIGIN` RPATHs. The Mojo runtime needs
  `GLIBCXX_3.4.30` (GCC 12), so the toolchain's libstdc++ is bundled too; `strip --strip-unneeded`
  takes it from 24 MB to 2.8 MB. The whole wheel is 2.6 MB.
- Redistribution terms for the bundled runtime belong to 17.81.

## Isolation test

`tests/test_python_binding.mojo`:

1. build the wheel;
2. create a fresh venv with `/usr/bin/python3` and `pip install --no-index` the wheel;
3. run `client_check.py` from a temp directory with `env -i PATH=/usr/bin:/bin`.

The client checks its own isolation: `/proc/self/maps` shows no shared library under the repo root,
and `sys.modules` holds no module from there. The Mojo side then compares the client's world hash with
a native `EmbedWorld` run of the same scenario, which is the scenario `test_capi`'s C host runs. All
three drivers give 16210273535471135586.

## Errors

| status | exception |
|---|---|
| `LD_ERR_ARG` | `ArgumentError` (also a `ValueError`) |
| `LD_ERR_STALE` | `StaleBodyError` |
| `LD_ERR_FORMAT` | `FormatError` |
| `LD_ERR_STATE` | `StateError` |
| `LD_ERR_HANDLE` | `HandleError` |
| `LD_ERR_BUFFER` | `BufferTooSmallError` (the binding sizes buffers itself, so users do not see it) |

The message is the engine's `ld_world_last_error` text. A Python exception raised inside a system or
contact subscriber makes the callback return non-zero. The step stops (a failing PRE system stops
before that tick's physics), and `step` re-raises the original exception with a `CallbackError` as its
`__cause__`.

## CVars

`CVarRegistry` holds typed variables (bool, int, float, str) with optional bounds and help text.

- `set` parses and checks the value, then notifies listeners.
- `exec("name value")` is the console form.
- `load(text)` validates every line before applying any.
- `dump()` round-trips through `load`.

`bind_world` defines `physics.iterations`, `physics.substeps` and `physics.gravity_{x,y,z}` with the
engine defaults, and applies changes from a PRE system at the next tick boundary. A change never lands
mid-tick, so it is bit-identical to calling `set_solver` / `set_gravity` at that boundary (tested).

## Hot reload

`HotSystem(world, path)` runs the module's `system(world, dt, tick, state)`.

- Before a tick (every `poll_every` ticks) it hashes the file. If the content changed, it re-executes
  the module and the new function takes over from that tick.
- The `state` dict persists across versions. The new module may define `migrate(state)`.
- If the new module fails (syntax error, exception at import, no `system`), the old function keeps
  running, and `last_error` / `failures` record the failure.
- Test: reloading at tick 60 gives the same hash as switching functions at tick 60. The test also
  covers a broken edit followed by a fixed one, with `migrate` called.

## Not here

- Mojo-side hot reload (experiment branch H1–H6).
- NumPy zero-copy views.
- CVars for engine parameters the C-ABI does not expose yet (sleep thresholds, restitution threshold).
- Publishing the wheel (17.81).
