# 17.0i — the runtime that owns a world, and the first system tests

Audit F15: nothing owns stateful runtime. A physics scene is neither a system nor a component,
nothing syncs `ContactScene6` poses into ECS transforms, and `System.apply[B](mut world)` is
stateless. 17.1 (controller), 17.7 (interpolation) and every gameplay feature need one home.
Test architecture: the `system` tier is empty because nothing wires ECS + scheduler + physics.

## `gameplay/runtime.mojo` (new package `gameplay`, layer 5 in scripts/arch_layers.toml)
- `Runtime[B: StorageBackend, Body: Body6]` owns: `world: World[B]`, `scene: ContactScene6[Body]`,
  `loop: FixedLoop`, `cfg: SolverConfig`, a contact-event channel (`scheduler.events`), timers
  (`scheduler.timers`), and `diag` counters it can surface.
- Components: `RigidBodyRef { id: BodyId }` links an entity to a scene body; the existing
  transform component(s) in `ecs/transform.mojo` / `ecs/motor_transform.mojo` receive the pose.
- `spawn_body(...) -> Entity` (adds the scene body AND the entity with RigidBodyRef + transform in
  one call), `despawn(e)` (removes both; uses BodySet.remove — if ContactScene6 still lacks body
  removal (17.0g-1 deferral), add `ContactScene6.remove_body(id)` here: tombstone the slot, drop it
  from colliders/broadphase/warm-start cache/joints referencing it → raise if joints reference it).
- `advance(frame_dt)`: FixedLoop fixed steps → each step: timers.advance(1), scene.step(dt, g,
  cfg), publish contact events to the channel, then sync poses → transforms (one system, reads
  BodySet, writes the transform component; ECS `for_each2`/query). Returns alpha (for 17.7).
- Move `ScrewBody`/`integrate_screw` (the ECS-coupled half of physics/screw.mojo, F15) into
  gameplay if it removes physics' dependency on ecs for the rigid path; keep `screw_velocity` /
  `step_screw` in physics. If the move is invasive, record why and skip.
- Architecture: gameplay may import every lower package; nothing may import gameplay
  (arch check enforces). Update docs/ARCHITECTURE.md §1 table row for gameplay.

## System tests (`# tier: system`) — end-state checks through the whole stack
1. `test_system_stack.mojo`: 10 box entities spawned via the runtime, advance 3 s of frames at an
   uneven frame rate (e.g. 1/144, 1/30 alternating) → every entity's transform equals its body pose,
   the stack is at rest (heights within 1e-3 of analytic), contact `began` events received once per
   touching pair, and sleeping kicks in.
2. `test_system_determinism.mojo`: two independent runtimes fed the same frame-dt sequence and
   spawn/despawn script → bit-identical transforms and identical event streams; then a snapshot
   (write_state) at frame 100, restore into a fresh runtime, continue → identical to the
   uninterrupted run.
3. `test_system_lifecycle.mojo`: spawn/despawn churn mid-simulation (entities with bodies,
   including one resting under another) → no stale transform writes, removed bodies stop colliding,
   ids recycled with new generations, counters sane; timers fire on the right ticks during it.
Extreme: 0 entities, one entity, despawn during a contact, frame_dt = 0, huge frame spike
(debt drop counted).
