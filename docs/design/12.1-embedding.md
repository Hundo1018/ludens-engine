# 12.1 Embedding boundary (C-ABI)

## What it is

The engine ships as a shared library, `build/libludens.so` (`pixi run capi`). It is built from
`embed/capi.mojo` and declared in `embed/ludens.h`. A host engine (Godot, Unity, Unreal, a Python
binding, a test program) drives a world through 35 C functions:

| group | functions |
|---|---|
| version | `ld_abi_version` |
| world | `ld_world_create` / `destroy` / `last_error` / `set_solver` / `set_gravity` / `tick` |
| bodies | `ld_body_add_box` / `add_sphere` / `remove` / `alive` / `set_velocity` / `apply_impulse` / `teleport` / `get_state`; `ld_world_body_count` / `get_bodies` |
| queries | `ld_world_raycast` |
| systems and events | `ld_world_add_system` / `remove_system` / `subscribe_contacts` / `unsubscribe` / `step` / `step_ticks` / `event_count` / `get_events` |
| save and restore | `ld_world_save_size` / `save` / `load` / `hash` |
| navigation | `ld_nav_bake` / `destroy` / `poly_count` / `find_path` / `last_error` |

The C functions are thin. Each one validates its handle, converts the arguments, and calls one method
of `embed.world.EmbedWorld` or `embed.navigation.EmbedNav`. Mojo hosts use those structs directly.

## Contract (v0.x)

- **Freeze.** `embed/abi_v0.txt` lists every frozen line: declarations, typedefs and status / phase /
  event constants. `tests/test_capi.mojo` checks:
  - each listed line is still in `ludens.h` verbatim;
  - the library exports exactly the functions the header declares (`nm -D`).

  Later minor versions may append functions and status codes. They never change or remove an existing
  line. `ld_abi_version()` returns `major << 16 | minor`.
- **Values only.** Everything crosses the boundary as plain values:
  - bodies are `int64` handles (`slot | generation << 32`);
  - poses are `float` x, y, z plus a quaternion x, y, z, w;
  - contact events are five `int64` (`ld_contact_event`).

  A handle to a removed body stays detectably dead after its slot is reused, because of the
  generation (tested).
- **Errors.** Return values:
  - `>= 0` means success, or a count / handle;
  - `< 0` is an `LD_ERR_*` code, and `ld_world_last_error` copies the message.

  Invalid input is validated once in `EmbedWorld` (a raise); the shim maps the raise to a code. No
  function raises across the boundary.
- **Buffers.** Output buffers are host-owned. If a buffer is too small, the call returns
  `LD_ERR_BUFFER` and writes nothing. The matching `*_count` / `*_size` call gives the size needed.
- **Stepping.**
  - `ld_world_step(frame_dt)` runs the `FixedLoop` accumulator: at most 8 ticks per call, and any
    excess debt is dropped.
  - `ld_world_step_ticks(n)` runs exactly `n` ticks.
  - Each tick runs: PRE systems → physics → contact subscribers → POST systems.
  - A non-zero return from a callback stops the step with `LD_ERR_CALLBACK`. The ticks already run
    stay run.
- **Re-entrancy.** Callbacks may call any function on the same world, except `ld_world_destroy` and
  `ld_world_load`, which are refused with `LD_ERR_STATE`. The tick loop is in the shim (`_run_ticks`),
  not in `EmbedWorld`. It re-reads the world through the raw pointer after every callback, so no Mojo
  reference is held while host code mutates the world.
- **Threads.** A world or navmesh is used from one thread at a time; different worlds are
  independent. Host job-system injection and asynchronous stepping belong to 17.75.
- **Units.** SI units (m, kg, s, rad); quaternions are x, y, z, w. Gravity is whatever the host
  passes. The default scenes use +Y up.
- **Handles.**
  - World and navmesh handles carry a magic word, so a null, foreign or destroyed handle returns
    `LD_ERR_HANDLE`.
  - The destroyed-handle check is best effort: destroying twice reads freed memory, which is a host
    bug, as with `free`.
  - Nullable pointers in the shim are `Optional[Pointer[...]]`. Mojo 1.1 pointers are non-null by
    design, and the optional form of a pointer is pointer-sized with NULL as `None`. A spike verified
    this against a C caller, and `test_capi` checks the NULL paths on every build.
- **Save.** The save blob is: magic, tick, accumulator, then the scene (`physics.serialize`, with
  island labels since 17.16). `hash` is FNV-1a over that blob.

## Evidence

`tests/test_capi.mojo` (integration tier, 54 checks):

- It builds the library and compiles `tests/capi/host.c` with `gcc -Werror`, then runs it.
- The C host drives a 13-body scene:
  - a PRE system written in C reads the player's state and sets its velocity every tick;
  - a C contact subscriber counts BEGAN and ENDED events.
- The scene runs 120 frames through `ld_world_step`, then 120 more ticks through `ld_world_step_ticks`.
- **Parity.** The same scenario runs natively on `EmbedWorld`, with the system as a Mojo loop. These
  match between the two runs:
  - the world hash;
  - the BEGAN and ENDED counts, from callbacks and from the event buffer;
  - the event total;
  - the player position;
  - the raycast body and `t`;
  - the navmesh path point count and length.

  This is the parity the ROADMAP asks for: driving the world from outside does not change the
  simulation.
- **Error paths.** Every documented code is exercised:
  - stale handle after remove and slot reuse;
  - NaN input, zero mass, unknown phase, NULL output;
  - short buffers for bodies, save, events and path;
  - corrupted and truncated blobs;
  - a failing callback (the step stops after 2 ticks);
  - destroy from inside a callback.

`benchmarks/bench_capi.mojo` measures the boundary: C host vs native for the same step, per-body state
reads, the batch pose read, and save / load.

## Not here

- 17.75: host job-system and allocator injection, async `begin` / `finish` stepping, `UnitScale`.
- 17.21: Python bindings, which will sit on this library or on `EmbedWorld`.
- 17.78: per-host adapters and host-defined components.
- 17.76: platforms other than Linux x86-64.
- Joints, shapes other than box and sphere, filters and materials. These are later minor versions: each
  adds functions, none changes an existing one.
