# 17.87 Hooks and generated docs

## Problem

- No hook existed: `.claude/` was empty, `.git/hooks/` held only samples. The documentation and governance
  checks that CI runs (`doclint`, `orphans`, `flag-policy`, `perf governance`, `bench-fresh`) failed only on a PR.
- Nothing generated a structure document. `docs/ARCHITECTURE.md` and the CLAUDE.md package table are hand-written
  and duplicate `scripts/arch_layers.toml`.
- `CHANGELOG.md` was last generated on 2026-10-12, 652 commits before this change.
- The ROADMAP subsystem table had drifted from the index in 4 of 13 rows; `roadmap-status` printed the
  difference but exited 0, so nothing failed.

## Decisions

**One rules file.** All hook logic is in `scripts/hooks.py` (standard library only, `--selftest`). The shell
wrappers in `.githooks/` and the entries in `.claude/settings.json` only call it, so a rule is tested in one place
and the git hooks and Claude hooks cannot disagree.

**Generate what is derivable, check what is not.**

| Document | Source | Mode |
|---|---|---|
| `docs/STRUCTURE.md` | `build/archindex.json` (`mojo doc`) | generated, `--check` in pre-push and CI |
| layer tables in CLAUDE.md / ARCHITECTURE.md | `scripts/arch_layers.toml` | checked only: the other columns are prose |
| ROADMAP subsystem table | ROADMAP index | checked only (`roadmap_status.py --check`) |
| `CHANGELOG.md` | git history | generated by `pixi run changelog`; warning only |

`CHANGELOG.md` has no `--check` because it lists commit hashes: the commits of the PR being checked can never be
in it. `pre-push` warns when the newest listed commit is more than 150 commits behind HEAD.

**`docs/STRUCTURE.md` content.** Per package in layer order, per module: traits, structs (non-default trait
conformances, method count), public function signatures, alias names. No line numbers, line counts or timestamps,
so an unrelated edit does not change it; names starting with `_` are left out (package-private, CLAUDE.md).

**pre-commit cost.** Rebuilding the index runs `mojo doc` and took 85 s on this repository, so regenerating the
structure document on every `.mojo` commit was rejected. `pre-commit` regenerates it only when the staged diff
adds or removes a declaration line in an engine `.mojo` file (`def`, `struct`, `trait`, `alias`, `comptime`).
A body-only edit skips it. A multi-line signature edited on a continuation line is missed there and caught by the
`--check` in `pre-push` and CI.

**Claude Code hooks.** PreToolUse returns exit code 2 with the reason on stderr, which Claude Code feeds back to
the model. The Bash rule inspects only what is executed: heredoc bodies and quoted strings are removed first. The
first version matched the whole command text and blocked a command that merely documented the rule (it happened
twice while writing this change). It is a guardrail, not a security boundary: `bash -c "..."` hides its payload.

**Not in a hook.** The full `pixi run gate` (about 2 hours with 4 jobs in CI) and `--update-golden`.

## Verification

- `pixi run hooks-selftest`: commit-subject cases, per-file check selection, declaration-line detection
  (including deleted files and non-engine directories), protected-path and Bash rules, tier-header rule,
  structure renderer determinism (reversed input gives identical output), layer-row parser, subsystem mismatch.
- Measured on x86-64: `pre-commit` without `.mojo` 0.82 s; `pre-push` 25.8 s for 11 checks; a commit that adds a
  declaration 85 s with the structure document regenerated and staged.
