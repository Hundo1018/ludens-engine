# 17.0b — test tiers, stamped mechanically

Contract: docs/ARCHITECTURE.md §3 (unit / component / integration / system / stress; performance
lives in benchmarks/). Tool: `pixi run arch -- tiers [--check]` (tools/archindex.mojo).

## Problem with the first rule
`tiers` computed a test's span as every package reachable TRANSITIVELY from its imports. Because
`physics` imports collision/ecs/numerics, every physics test came out "integration", and a test of
`geometry.aabb` alone came out "component". Transitive reach says what a test could touch, not what
it exercises.

## Rule (mechanical, reproducible)
Let D = engine modules the test file imports directly, excluding `harness.*` and `diag.*`.
Let span = packages(D) ∪ packages directly imported by the modules in D (one hop: the entry
point's own wiring), minus `geometry` when anything else remains (geometry is the math base
everything uses).
- `stress`: file name `test_stress_*`, or a `# tier: stress` override kept by hand.
- `system`: D includes `scheduler.gameloop` (or `gameplay.runtime` once it exists) AND an `ecs`
  module AND a `physics` module.
- `integration`: |span| ≥ 2.
- `component`: |span| = 1 and (|D| ≥ 2, or the test imports ≥ 2 structs conforming to the same
  trait — a seam exercised across variants).
- `unit`: otherwise (one module under test).
A human override is allowed only with a reason on the same line:
`# tier: component  (override: exercises all six broadphase backends through one trait)`.
`tiers --check` accepts an override when it carries `(override: ...)`.

## Deliverables
1. Implement the rule in tools/archindex.mojo `tiers`; extend `selftest` fixtures with one test
   file per tier (+ one override) and assert the computed tier.
2. Stamp every tests/test_*.mojo with a first line `# tier: <tier>` (keep the module docstring
   right after it). Report the distribution and list every file where the stamp differs from the
   earlier hand classification seed (.campaign/test_tiers.tsv, local-only) with a one-line reason.
3. Runner: scripts/run_tests.sh takes an optional tier list (`run_tests.sh unit component`);
   pixi tasks `test-unit`, `test-component`, `test-integration`, `test-system`, `test-stress`;
   `test` = unit+component+integration+system (in that order: fastest feedback first);
   `test-all` = all five. The runner fails a file with no/invalid header.
4. `arch-check` runs `check` AND `tiers --check`.
5. Gates: full suite green, 0 warnings; normalized stdout identical to golden (headers are
   comments; ORDER of files changes only if the runner orders by tier — then compare sorted
   per-file sections instead of raw order).
