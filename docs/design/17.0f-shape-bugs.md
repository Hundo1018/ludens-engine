# Spec 17.0f — four shape-handling bugs, red test first (audit F3, F4; hotspots E8–E11)

Precondition: 17.0e landed (collider registry in collision/collider_set.mojo; sites marked `# 17.0f:`).
Method (TDD): for each bug, FIRST add a failing test and paste its red output, THEN fix, THEN
paste green. Tests go in tests/test_shape_dispatch.mojo (`# tier: integration`) unless a bug
belongs naturally in an existing file.

## Bugs
F3 / E10 — static trimesh/heightfield bounds. `add_trimesh`/`add_heightfield` keep only
`bounds().half_extents()` and the fat AABB is centred on the body pose, though the docs say the
body pose of a static mesh is ignored. Red test: a heightfield whose vertex bounds are NOT centred
at the body position (e.g. heights spanning x∈[10,30]); drop a box onto it; run brute
(`broadphase=False`) and seam (`broadphase=True`) for 200 steps → today the seam path lets the box
fall through (or brute ≠ seam). Fix: ColliderSet stores the static collider's WORLD AABB and
`fat_aabb` returns it for mesh kinds. Green: both paths rest on the surface and agree bit-for-bit.

F4a / E8 — sensor vs trimesh/heightfield falls into the capsule-capsule catch-all. Red test: a
sensor box overlapping a trimesh floor and one NOT overlapping it (but within the mesh's bounds
sphere) → today overlap/events are wrong for at least one. Fix: exhaustive dispatch over kind pairs;
sensor-vs-mesh uses the mesh triangle candidates path (same as solid bodies, without impulses);
any unsupported kind pair → `abort("unsupported collider pair ...")` (programmer error class —
unreachable after exhaustive dispatch; prove unreachability with a comptime table if natural).

F4b / E9 — soft-body particles treat hull/trimesh/heightfield colliders as a sphere of radius
`half.x` at the body position. Red test: a soft lattice resting on (1) a hull, (2) a trimesh floor
not centred at the body origin → today particles float on an invisible sphere or fall through.
Fix: particle-vs-collider query goes through ColliderSet (point-vs-shape closest point / signed
distance for every kind; hull via its faces, mesh via triangle candidates + closest point on
triangle, heightfield via height sample + normal).

F4c / E11 — CCD (`step_soft(ccd=True)`) sweeps every body as its `half` box, ignores
`should_collide` and sensors, and uses level bounds as a box. Red test: (1) a fast body passing
THROUGH a sensor volume must not be clamped at the sensor; (2) a fast body whose mask excludes a
wall must pass through the wall; (3) a fast body over a large trimesh floor must not be clamped at
the floor's bounding box top when the actual surface is lower. Fix: CCD consults
`should_collide`, skips sensors, and for kinds without an exact TOI (hull/trimesh/heightfield)
either uses a conservative per-kind sweep or is rejected at the API: `step_soft(ccd=True)` raises
if such a pair is a CCD candidate (policy: invalid-input class) — choose the smaller correct option
and document it in the module docstring.
