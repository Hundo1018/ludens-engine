# 17.15 AI 框架

## 問題

引擎只有 FSM / HSM(`procedural/fsm.mojo`)。ROADMAP 17.15 要求 behavior tree、utility AI、blackboard、
perception、EQS,以及增補的轉向 / 群聚 / 隊形、GOAP / HTN、smart objects、影響力圖 / 戰爭迷霧;
seam 是「BT vs FSM vs utility(vs planner)對同一決策問題行為等價 + tick 成本」。

## 放在哪一層

新套件 `ai`,layer 4(與 `physics` 同層,互不 import)。它用 `nav`(EQS 投到 navmesh、路徑長)、
`procedural.fsm`(FSM 決策變體)。**不** import `collision` / `physics`:感知的視線是兩階段 ——
`sight_candidates` 給出射線、宿主用自己的世界查詢(`ContactScene6.ray_cast`、`ray_cast_batch`、
navmesh raycast…)批次判定、`commit_sight` 收回結果。這讓 AI 不綁特定碰撞後端,也符合平台方向 C
(C-ABI 下宿主本來就擁有世界查詢)。`test_ai_world` 在測試層把它接上物理世界。

## 行為樹

定義是共享的扁平陣列,每個 agent 一個 `BtState`(running child、計數器、冷卻、parallel 子節點完成狀態)。
葉節點由宿主的 `BtHost`(comptime 泛型)執行。記憶式 composite 從上次 running 的子節點繼續;reactive
composite 每 tick 從第一個子節點重評,搶占時以 `BtHost.abort` 中止原本 running 的分支。

tick 是迭代:第一版遞迴在約 2000 層 decorator 鏈時爆堆疊(roadmap 的極端案例「深遞迴」),改成顯式
frame 堆疊,堆疊放在 `BtState` 內重用,避免每 tick 配置(配置佔了 13 節點樹 1 µs 中的大半,改後 249 ns)。

## 決策 seam 的定律

四個變體(BT / FSM / utility / GOAP)並非互相比對,而是都對同一份規則清單(oracle)比對:
600 tick 的劇本(巡邏 → 發現 → 追擊 → 攻擊 → 失去視線 → 搜索 → 放棄 → 巡邏 → 受傷時發現 → 逃跑)
與 2000 個種子隨機黑板。FSM 版本的守衛條件必須互斥(否則多步轉移的結果依列順序而定),測試裡
的 FSM 就是這樣寫的。GOAP 版本把「相關性」放在目標上(第一個相關且未滿足的目標才規劃)。

## 量測到的失敗與修正

- 群聚:以全速 seek 做 cohesion、沒有最低速度時,密集魚群停滯、方向抖動,局部對齊只有 ~0.5;
  改成比例式 cohesion 更差(變成煞車)。Reynolds 的 boids 以近乎固定的速度飛行 —— 加上 `min_speed`
  後所有密度與力上限設定都收斂到 0.999。
- Parallel 節點第一版每 tick 重 tick 已完成的子節點,動作被重新開始;改為記住完成狀態直到 parallel 結束。

## 已知限制

- 感知候選是 O(觀察者 × 目標) 暴力(1000 × 1000 = 7.4 ms);大量時應換成空間格。
- EQS 排序是插入排序(441 點 149 µs)。
- BT tick 逐 agent 串行;roadmap 提到的「入 10.2 job graph 依讀寫集平行」未做。
