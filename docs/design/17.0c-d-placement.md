# 17.0c + 17.0d — placement moves and shared geometry primitives (behaviour-preserving)

Evidence: docs/audits/2026-09-27-architecture.md findings F6, F7, F8, F13, F17 (placement part),
F18, F24. Every step is behaviour-preserving: the normalized test output must not lose or change
a single golden line (compare sorted: `diff <(sort .campaign/golden_test_stdout_1.1.0.txt)
<(bash .campaign/normalize.sh LOG | sort) | grep '^<'` → empty). One commit per numbered step.

1. **Acceleration structures to `spatial`** (F17 placement, §3(b)): `geometry/bvh.mojo` and
   `geometry/gpu_lbvh.mojo` → `spatial/`. `spatial`'s charter is "spatial indexes over AABBs"; this
   takes `max.gpu` out of the math root package. Update every importer
   (`pixi run arch -- uses geometry.bvh`, `uses geometry.gpu_lbvh`). Layer check must stay OK
   (spatial = 2, collision = 3 imports it — legal).
2. **One `WorldType`** (F6): `ecs/system.mojo`, `physics/serialize.mojo` and the GPU modules
   hard-code float32; make them derive from `geometry.vec.WorldType` (serialize's on-disk format
   may keep writing float32 bit patterns — then say so explicitly in its docstring and assert at
   comptime that `WorldType == DType.float32` so a future f64 switch fails loudly, not silently).
3. **Contact clipping to collision** (F24): `geometry/clip.mojo` → `collision/clip.mojo`
   (its only user is collision/manifold.mojo).
4. **FSM below the animation graph** (F7): `scheduler/fsm.mojo` → `procedural/fsm.mojo`
   (no imports, no engine users; 17.6's animation graph in `procedural` must be able to use it).
   Fix `procedural/anim.mojo`'s first docstring line, which promises a state machine it does not
   contain.
5. **Dead `raises`** (F13, error policy rule 3): drop `raises` from signatures that can never
   raise (chain FK/RNEA/CRBA/ABA sweeps, quickhull, and the others `pixi run arch -- raises <pkg>`
   lists) — the compiler tells you when a caller no longer needs `try`. Keep real raise sites.
6. **Intra-package private reach-through** (F18), except serialize's (17.0g replaces it):
   `vbd_cloth` → `_init_grid`, `mpm` → `fem._det3` (becomes geometry `Mat3x3.det`, step 7),
   `sph` → `pbf._H` (make the kernel radius a per-fluid parameter or a named public constant with
   a docstring saying the two solvers share it deliberately), `gmv` sign tables,
   `ecs/system.mojo` → `ArchetypeBackend._slot_of/_col` (promote to documented public methods;
   drop the stale comment about ecs not depending on geometry), `softbody` public `List[_SP]`.
7. **Shared primitives** (F8): in `geometry/vec.mojo` public `cross(a, b)` and
   `tangent_basis(n) -> (t1, t2)`; new `geometry/mat3.mojo` with a linear `Mat3x3`
   (`matvec`, `mul`, `transpose`, `det`, `skew(v)`, `from_rows/cols`) — `geometry/mat.mojo`'s
   `Mat3` is a 2-D affine and stays. Replace the 11 private cross-product copies
   (epa, gjk, quat, toi, manifold, floating, rigid6, integrator6, chain, sensors, solver6),
   `_tangent_basis` (solver6) / `_basis` (collision/hull), `fem._det3`, and chain's `_Rows3`
   helpers. **Identity:** if two copies compute the same thing with a different operation order,
   float results can differ in the last bit — the golden gate will show it. Resolve by giving the
   shared function the operation order of the copy whose callers' outputs are in the golden, and
   if a second order is genuinely needed keep a separately named variant with a comment. Do not
   accept a changed golden line.
