# Spec 17.0e — ColliderSet + contact generation over the BroadPhase seam

Source of truth for the problem: docs/audits/2026-09-27-architecture.md §1.1 (clusters 2, 6, 7), findings F1, F2
(and F3/F4 context — but those bug fixes are 17.0f, NOT this step). ROADMAP 17.0e.

## Goal
Collision responsibilities currently implemented inside `physics/solver6.mojo` (layer 4) move to
`collision/` (layer 3) so that (a) 17.13 scene queries and 17.1 character controller can use the
real collider geometry without importing physics or reaching into `ContactScene6` fields, and
(b) the 3-D solver's candidate pairs come from the `BroadPhase` seam (collision/broadphase.mojo)
instead of an inline throwaway BVH, so the seam benchmarks measure the path the engine runs.

**This step is behaviour-preserving.** Identity gate: the normalized stdout of the whole test
suite must be byte-identical to .campaign/golden_test_stdout_1.1.0.txt (normalizer below).

## Target shape
- `collision/collider_set.mojo`: `ColliderSet` owns, per collider index (same index as the body):
  kind (box/sphere/capsule/hull/trimesh/heightfield — named comptime constants), half extents,
  hull table + hull_id, mesh/field tables + mesh_id, category/mask, sensor flag. Methods (public,
  documented): `add_*` registration mirroring today's `ContactScene6.add*` shape part,
  `should_collide(i, j)`, `is_sensor(i)`, `fat_aabb(i, pose, spec_margin)`, `as_hull(i, pose, ...)`,
  `pair_manifold(i, j, pose_i, pose_j, ...)`, mesh candidate/triangle helpers — everything in
  audit cluster 6. A pose is passed in (`Pose3`: position `Vec3` + `Axes3` rotation — reuse
  `collision.manifold.Axes3`); collision never sees `Body6`.
- `collision/contact_gen.mojo` (or methods on ColliderSet — choose the smaller clean design):
  candidate enumeration through a `BroadPhase` instance + the per-pair `try_pair`/`try_mesh_pair`
  detection that produces manifolds and sensor overlaps. Warm-start matching and impulse prep
  (anchors, restitution prep) stay in physics — contact_gen returns geometry only.
- `collision/contact_events.mojo`: `ContactEvent`, key packing, began/stay/ended diff (cluster 2).
  Replace the private merge sort with stdlib `sort` if a probe shows it is a stable/total order on
  Int (it is a plain Int sort — any correct sort gives identical output).
- `physics/solver6.mojo`: `ContactScene6[B: Body6, BP: BroadPhase = <BVH broadphase, dim 3>]`
  holds `colliders: ColliderSet` and `bp: BP`. `broadphase=True` in `step_soft` enumerates via
  `self.bp` (rebuild with fat AABBs, pairs, filter j>i & not static-static, sort by (i, j)) —
  this ordering is what makes it bit-identical to the nested-loop path. `broadphase=False` keeps
  the nested loop as the reference. The existing public registration API (`add`, `add_sphere`,
  `add_capsule`, `add_hull`, `add_trimesh`, `add_heightfield`, `set_filter`, `set_sensor`,
  `set_restitution`) keeps its signatures and delegates. Read-access that tests use today
  (`sc.shape`, `sc.hull_id`, `sc.meshes`, `sc.category`... see `git grep` outside solver6) moves
  to `sc.colliders.<...>` — update call sites.
- `BroadPhase` trait: if every implementation can be non-raising (1.1.0 `List.append` does not
  raise — probe), drop `raises` from the trait methods (audit F13); otherwise call through
  `try/except` that `abort`s (programmer-error class, docs/ARCHITECTURE.md §2).
- Serialize (`physics/serialize.mojo`) must keep round-tripping bit-identically (it will be
  properly fixed by 17.0g's snapshot API; here just follow the moved fields).

## Seam deliverables (定律 v2/v3)
- Parity test: every BroadPhase implementation that is dimension-3 capable (brute, BVH, DBVH,
  SAP, hash grid, octree — check which support dim 3) plugged into ContactScene6 gives a
  bit-identical 200-step trajectory to the nested-loop reference on (a) a box stack, (b) a mixed
  scene with a trimesh floor + hull + spheres + capsules, (c) an extreme case: 0 bodies, 1 body,
  all bodies overlapping at one point, a teleport mid-run (breaks DBVH temporal coherence).
  Extend tests/test_solver_broadphase.mojo or add tests/test_solver_bp_seam.mojo (`# tier: integration`).
- Benchmark: extend benchmarks/bench_solver_scale.mojo (or new bench) with rows per BroadPhase
  in the solver at N = 64 … 4096 bodies (the regime where the persistent DBVH's frame coherence
  should win over rebuild-per-step BVH — advantage-regime rule: measure where each should win,
  e.g. uniform vs 20:1 size spread for SAP/hash grid). Add prose + `@bench` marker in
  scripts/benchmark_report.md.in, and a seam row in docs/CATEGORY.md §2.
