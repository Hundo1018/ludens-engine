# 17.88 Mojo 1.2.0 upgrade and adoption of the new features

Issue #67. Results and numbers are in the ROADMAP 17.88 entry; this note records the decisions.

## Order of work

1. Pin `mojo ==1.2.0`, `modular ==26.7.0`; `pixi update modular mojo` (not a full `pixi update`, which also
   moves python 3.14 -> 3.13 and unrelated packages).
2. Build, run the gate on the upgrade-only commit, review the golden.
3. Adopt features one family at a time, each as its own commit, each judged by the gate golden.
4. Attribute every changed golden section to the toolchain or to a refactor by running the same test on the
   upgrade-only export and on the refactored tree (`pixi run` with the shared `.pixi` symlinked into an
   `git archive` of the commit, so the two runs cannot interfere).

## Facts established by probes on 1.2.0

- `case NAME:` with a `comptime` constant is a capture pattern and matches every value (the compiler only warns
  "case is unreachable"). `case == NAME:` compares, in `match` and in `comptime match`. Literal ints are fine bare.
- A `Defaultable` struct without an `__init__` gets one that default-constructs every field (Int 0, Float 0.0, Bool
  False, List empty). The compiler derives it from the fields, so every field type must itself be `Defaultable`
  (this is what broke `BVHBroadPhase` until `BVH` declared the trait).
- `if case .Some(v) = opt` binds `v` immutably; use `if case .Some(ref v) = opt` when the callee takes it `mut`.
- A struct that stores a function-typed parameter does not compile (`Tween[T, type_of(f), K]`); an empty struct
  implementing a trait does. Not fixed by field order, extra fields, the bound on `T`, or the argument form.
- The same arithmetic can round differently as `match` than as `if/elif` (`physics/mass_props.mojo`); only a
  bit-for-bit test (`test_compound`) noticed.

## Not adopted

`Tuple.first_of` (finds a tuple element by type; `_slot_of` maps an `ID` to an index), `comptime match T`
(`WorldType` is a `DType` value), `where ... else` / `not Movable` (no old spelling in the repo), GPU `std.math`
(no hand-written replacement in the repo, and no GPU on the build host).

## Tools added

`scripts/chain_to_match.py` (if/elif chain -> match; skips a chain marked `if/elif on purpose`),
`scripts/defaultable_scan.py` (redundant zero-argument `__init__`), `scripts/fix_noop_transfers.py` (the `^` the
compiler reports as having no effect). Each has `--selftest`.
